Architecture Atlas · v0.1 · all components run locally

Tessera

A local data-engineering and analytics platform with an AI analyst. One repository, one Python process, one DuckDB file, one local LLM server. Every diagram below describes what is in the repo today; the last tab lists what is deliberately not built yet.

System context

Three processes on localhost. Nothing leaves the machine: model calls go to Ollama on 127.0.0.1:11434.

Data layers & the model DAG

Raw files land untouched, are typed and de-duplicated in staging, and are shaped into analytics-ready marts. The DAG is not configured: it is derived from {{ ref() }} and {{ source() }} in the SQL.

Fig. 2 · Lineage as of v0.1 (drawn by hand; the live, generated version is the Pipelines tab in the app)

Conventions

LayerRuleExample
rawNo transformation; all columns text; lineage columns _loaded_at, _source_file; reload only if SHA-256 changedraw.orders
stagingCast types, normalise strings, row_number() de-duplication on the business keystg_orders collapses 40 replayed rows
martsFacts and dimensions at a declared grain, materialised as tablesfct_orders = one row per order
The generator plants real defects: duplicate customers with messy casing, replayed orders, 3% missing emails and one orphan foreign key. The quality suite is expected to catch the last two on every run.

Jobs & data quality

Every task is recorded in meta.runs. Quality is a gate, not a log line.

Fig. 3 · The pipeline task

TaskDoesTriggered by
generateRewrites synthetic source filesCLI
ingestLoads changed files into raw.*CLI · UI · scheduler · agent (approved)
transformBuilds models in topological order; select rebuilds a model plus its downstreamsame
qualityRuns tests, fails the run on errors, warns on warningssame
pipelineingest → transform → qualityserve --schedule N

Quality tests (declared in models/schema.yml)

not_null · unique · non_negative · relationships (foreign key) · row_count_min · severities error / warn. A single-flight guard stops overlapping runs of one task; statuses are success, quality_failed, failed.

The AI analyst

A local tool-calling model. The model proposes; deterministic code disposes. It never sees raw tables or PII, it cannot write without a click, and numbers it quotes are checked against query results.

Honest limit. A 3B model on CPU writes decent SQL and self-corrects from the error's valid_columns hint, but misreads digits when paraphrasing results. Mitigations built in: the result table is always shown, ungrounded numbers raise a warning, and TESSERA_CHAT_MODEL=qwen2.5:7b is a one-line upgrade.

Privacy & guardrails

Each control is enforced in code and covered by a test.

ThreatControlWhere
Model writes destructive SQLParsed with sqlglot; one SELECT only; DDL/DML, COPY, file functions rejectedai/guard.py
Model reads unstaged or system dataOnly schema-qualified marts.*/staging.*; raw and meta blockedguard.py
PII exposurepii: true columns in schema.yml cannot be selected; SELECT * on such tables rejected; excluded from prompt and samplesguard.py, agent.py, tools.py
Unwanted side effectsWrite tools pause for a human approval, decisions are audited; declined = nothing runsagent.py
Hallucinated figuresNumeric grounding check against this turn's tool outputagent.ungrounded_numbers
Unbounded memoryConsent switch, user-only extraction, definitions/preferences only, list and deleteai/memory.py
Data leaving the machineOnly Ollama on localhost is called; no telemetry, no CDN assetsai/gateway.py

Operational notes

  • DuckDB allows one writer process: stop the server before running tessera pipeline from the CLI, or trigger tasks from the UI.
  • Single-user by design: no auth on 127.0.0.1.
